## Contention run

Command: `go run ./cmd/percolator-txn contend -workers 8 -txns 20000 -accounts 1000 -seed 1`

```
workers=8 txns=20000 accounts=1000 seed=1
prewritten=487 write_conflicts=0 key_locked=19513 locks_held=974
elapsed=56ms (355136 txns/s)
invariants: every prewritten txn holds all its locks under one primary; aborted txns hold none: OK
```

Reading it: M1 has no commit phase, so a successful prewrite keeps its two locks. Once 487
transactions held 974 of the 1,000 accounts, every later transfer met a lock (`key_locked`).
There are no write conflicts because nothing commits during the run. The point of the run is
the invariant check on every lock, not throughput; meaningful throughput needs M2.

## Benchmarks

Command: `go test -run '^$' -bench . -benchmem -benchtime 2s .`

| Benchmark | Time per op | Allocations |
|---|---|---|
| OracleNext (one caller) | 114 ns | 0 |
| OracleNextParallel (20 threads, one mutex) | 196 ns | 0 |
| SnapshotGet (10,000 keys x 10 versions) | 1.75 µs | 2 allocs, 39 B |
| Prewrite2Keys (begin, 2 sets, prewrite) | 6.2 µs | 27 allocs, 1,268 B |

- The oracle mutex costs ~114 ns uncontended and ~196 ns with 20 threads, so in-process it is
  not a bottleneck at these rates; a networked oracle would need batching (ADR 0002).
- `SnapshotGet` time includes `fmt.Sprintf` for the key in the loop and a linear scan of the
  write list (10 versions); a long history would need a sorted search, which is M2/M3 work.

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | A transfer touching two keys must never be half-applied. M1 targets: strictly increasing timestamps, reads equal to an SI reference model, no key locked twice, no lock left by an aborted prewrite, bounded inputs ([RFC 0001](../rfc/0001-design.md)). |
| Measure | 30 tests, 200 x 400-operation random histories, a 20,000-transaction contention run and four micro-benchmarks on the machine above with Go 1.26.9. |
| Analyze | All targets met: 0 duplicate timestamps, 0 model mismatches, 0 double locks, 0 leaked locks. One defect was found during development, in a test: the random-history test started its clock at 1, so a start timestamp drawn from the past could be 0, which the store correctly refuses. One formatting defect (a `sed` edit) was caught by `gofmt`. |
| Improve | The test clock now starts at 10; the formatting was fixed with `gofmt -w`. A mutation check (above) confirmed the property test detects a visibility off-by-one. |
| Control | CI (`make ci`) runs gofmt, `go vet` and the tests with the race detector, then the contention invariant check and govulncheck on every push and pull request. In code: typed errors for conflicts, validated key/value/mutation bounds, copied inputs, and `.tmp/check.sh` for local reruns. |
